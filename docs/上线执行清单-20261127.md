## 三、绑定分包商账号（02 建表后必须做，否则外部账号看不到数据）

```sql
-- 绑定示例：把邮箱 xxx@yyy.com 的账号绑到合作方（分包商/货主）
INSERT INTO public.user_partners (user_id, partner_id, is_primary, relation)
SELECT pr.id, pa.id, true, 'owner'
FROM public.profiles pr, public.partners pa
WHERE pr.email = 'xxx@yyy.com'
  AND pa.name = '山西成丰运输'
ON CONFLICT (user_id, partner_id) DO UPDATE SET is_primary = true;

-- 校验：每个外部账号都应恰好有一条
SELECT pr.email, pr.role::text, pa.name, up.is_primary
FROM public.user_partners up
JOIN public.profiles pr ON pr.id = up.user_id
JOIN public.partners pa ON pa.id = up.partner_id
ORDER BY pr.email;
```

> 没有绑定的账号调用 `partner_*` 接口会返回 42501「当前账号未绑定合作方」，不会看到任何数据（偏保守，不越权）。

**金额快照（执行 01 前、全部执行后再各跑一次，必须一致）**
```sql
SELECT count(*) AS cost_rows,
       sum(payable_amount) AS sum_payable,
       sum(base_amount)    AS sum_base
FROM logistics_partner_costs;

SELECT count(*) AS record_rows,
       sum(payable_cost) AS sum_payable_cost,
       sum(current_cost) AS sum_current_cost
FROM logistics_records;
```

> 这组数字不变 = 证明「没有动过现有金额」。任何一步之后数字变了，立即回滚该步。

## 七、出问题时怎么退

| 步骤 | 退法 | 影响 |
|---|---|---|
| 01 | `ALTER COLUMN chain_id DROP NOT NULL`; `DROP INDEX uk_pp_chain_level` | 无 |
| 02 | `DROP TABLE user_partners CASCADE` | 外部账号立即失去访问（偏安全） |
| 03 | 重跑 `20251124_replace_all_hardcoded_permissions_1126.sql` 原函数 | 换链路行为回到旧版（翻倍风险回来） |
| 04 | `ALTER TABLE logistics_partner_costs DISABLE TRIGGER trg_lpc_reverse_balance_on_delete` 等 | 余额回到只扣不回补 |
| 05 | 见文件末回滚注释（删字段 → 归属丢失，金额不变） | 无 |
| 06 | `DROP FUNCTION get_chain_profit_report / get_chain_structure / get_receivable_aging` | 毛利页报错 |
| 07 | `DELETE FROM menu_config WHERE key='finance.chain_profit'` | 菜单消失 |
| 08/09 | `DROP FUNCTION` / 删策略 | 门户不可用，内部系统不受影响 |
